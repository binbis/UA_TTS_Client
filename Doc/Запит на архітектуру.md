У мене є python tts сервер та `UA_TTS_Client.exe`.

Коли я остаточно переїхав з win11 на endeavour os я втратив вихідний код  __csharp__ застосунку. Оскільки `UA_TTS_Client` створювався виключно під win11, на Linux, інтерфейс працює некоректно через використання *wpf* та *libreautomate*.

Я хочу написати створити абсолютно новий `UA_TTS_Client` застосунок. 

Вже створив __rider project__ з шаблонним формування Mvvm. Писатиму мовою  __csharp__. Поточні налаштування [UA_TTS_Client.csproj] надаю.  Оскільки моя програма націлена під Wayland, який створювався з акцентом на безпеку, я встановив допоміжні пакети: ydotoold, wl-clipboard та xsel. Також, щоб `ydotool` міг звертатися до віртуальної клавіатури в ядрі (`/dev/uinput`) без root-прав, додав свого користувача до системної групи `input`.  Усе це необхідно для SharpHook та TextCopy, щоб імітувати дії клавіатури користувача.

Я вбачаю декілька інтерфейсів:
1. Основний, що відповідатиме за повсякденне використання: озвучка через копіювання тексту будь-де, зчитування буфера обміну. Саме тут буде працювати глобальне поєднання `alt+q`.
2. Tab-Секція, що відповідатиме за озвучування книг, файлів форматів `txt`, `pdf`, `word`, `odt`.
3. Tab-Секція, що відповідатиме за створення озвучки персонажів з комп'ютерних ігор. (Наразі лише концепція, яка не реалізована та не продував деталі).
4. Tab-Секція налаштувань конфігурацій кожної Tab-Секція через `checkboxs`, `sliders`, `inputs`, тощо.

Дана структура згенерована автоматично як базовий шаблон. Складати все у один кошик - майбутні проблеми з підтримкою. Оскільки мої цільові ОС - Linux (EndeavourOS/Arch) та Windows 11, мені потрібно використовувати архітектурні підходи, кросплатформність та Clean Code:
- Код ПОВИНЕН гарантовано працювати як на Linux, так і на Windows 11. Обов'язково використовуй `Path.Combine` або `Path.Join` для побудови шляхів. Уникай хардкоду слешів (`\` чи `/`) та завжди пам'ятай про чутливість до регістру у файлових системах Linux.
- Дотримуйся принципів SOLID, DRY, KISS та YAGNI.
- Впровадження залежностей (Dependency Injection): Активно використовуй `Microsoft.Extensions.DependencyInjection`. Всі сервіси, ViewModel та інші залежності мають реєструватися через `ServiceCollection` (використовуючи `AddTransient`, `AddSingleton`, `AddScoped`). Передача залежностей має відбуватися виключно через конструктори.
- Виділяй чіткі шари (DTO, Сервіси, UI-шар на Avalonia). Розділяй бізнес-логіку та логіку UI.

Краще для кросплатформного відтворення звуку (IAudioPlayerService) підійде ManagedBass. Avalonia не містить вбудованого аудіо-движка. Для Linux (PipeWire/PulseAudio) та Windows 11 потрібне стабільне кросплатформне рішення. Варіант який я буду використовувати це ManagedBass. Тому вже встановив пакет `yay -S bass`.

Перед тим як писати код, мені потрібна зрозуміла архітектура проєкту. Треба закладати можливе розширення застосунку. Також варто закладати зручну підтримку коду, накшталт модульності та керування files-tree на майбутнє. Допоможи побувати структуровану архітектуру з поясненнями.
